# [서비스 기획서] 버즈48 (Buzz48) : 48시간 타임어택 실시간 게시판 플랫폼

> **버전**: v2.1 | **최종 수정**: 2026-07-03

---

## 1. 서비스 개요

* **서비스명(가칭)**: 버즈48 (Buzz48)
* **한 줄 정의**: 게시글이 곧 채팅방이 되는, 48시간 동안만 살아있는 실시간 게시판 플랫폼
* **핵심 타깃**: 실시간 이슈와 트렌드에 민감하고, 즉각적인 의견 교환을 원하는 2040 인터넷 사용자
* **기획 배경**:
  * 기존 게시판(커뮤니티)은 정적인 **댓글 구조**로 인해 빠르게 터지는 이슈의 속도를 따라가지 못하며, 새로고침을 반복해야 하는 피로감이 존재함.
  * 디스코드·텔레그램 등 실시간 채팅 플랫폼은 소통이 원활하지만, 초대 링크 기반의 폐쇄적 구조로 인해 새로운 유저가 실시간 이슈에 즉각 진입하기 어려움.
  * 온라인 커뮤니티의 댓글창은 오래된 글에도 무한히 도배·악성 댓글이 누적되어 운영 부담이 가중됨.
  * 이에 따라 **게시판의 '접근성'**과 **채팅방의 '실시간성'**을 결합하고, **대화의 유효기간**을 두어 콘텐츠 노후화와 도배 문제를 원천적으로 차단하는 게시판 플랫폼을 기획함.

## 2. 핵심 가치 및 차별화 포인트

1. **댓글이 아닌 채팅 (Chat, Not Comment)**: 기존 커뮤니티의 정적인 댓글을 폐기하고, 웹소켓(WebSocket) 기반의 실시간 채팅 UI를 기본 소통 방식으로 채택. 게시글 하나가 생성되는 순간, 그 자체가 독립된 채팅 채널을 가진 게시물이 됨.
2. **48시간 휘발성 (FOMO & Lifecycle)**: 모든 게시글(게시물)은 최대 48시간 동안만 생존함. 24시간이 지나면 '읽기 전용'으로 전환되고, 이후 24시간이 지나면 영구 삭제됨. 유저에게 *"지금 참여하지 않으면 놓친다"* 는 강력한 FOMO(소외 불안감)를 자극하여 즉각적인 참여를 유도함.
3. **진입 장벽 제로 (Zero Friction)**: 복잡한 회원가입 없이 접속 즉시 임시 닉네임이 부여되어 1초 만에 채팅 참여 가능. 계정 없이도 읽기와 채팅이 자유롭게 허용됨.
4. **자기 정화하는 플랫폼 (Self-Cleaning Platform)**: 콘텐츠가 48시간 후 자동 소멸되기 때문에 운영 부담 없이 플랫폼이 항상 신선한 이슈로 채워지며, 묵은 도배글과 악성 댓글이 자동으로 제거됨.

## 3. 화면 구조 및 UI/UX 설계

### 3.1 메인 화면 (게시판 타임라인)

* **상단 [HOT 게시물 카드 존]**
  * 현재 실시간 동접자 수 및 채팅 밀도가 가장 높은 상위 3개 게시물을 대형 카드 형태로 고정 노출.
  * 현재 가장 뜨거운 이슈가 자연스럽게 상단에 배치되어 유저 트래픽을 집중시킴.
  * 카드에는 `[🔥 지금 432명 참여 중]`, `[⏱ 08:22:14 남음]` 등 실시간 정보를 시각적으로 표시.

* **중단 [카테고리 탭 필터]**
  * 전체 / 사회·정치 / 경제·주식 / 스포츠 / 연예·문화 / 가상자산 / 자유 등 주요 카테고리 탭 제공.
  * 유저가 관심 카테고리를 선택하면 해당 게시물만 필터링되어 노출.

* **하단 [일반 게시판 리스트 존]**
  * 최신순 정렬을 기본으로 하는 텍스트 기반 게시판 리스트.
  * 각 행에 `[💬 실시간 참여자 수]` 및 `[🟢 LIVE | 14:22:05 남음]` 타이머를 실시간으로 시각화.
  * 상태 배지: `🟢 LIVE` (채팅 가능) / `🟡 READ` (읽기 전용) 구분 표시.

### 3.2 게시물 상세 화면 (분할 레이아웃)

게시물 리스트에서 특정 게시물을 클릭하면 나타나는 상세 화면으로, 정보 인지와 실시간 소통이 동시에 가능하도록 **좌/우 2분할 레이아웃**을 채택함. (모바일의 경우 탭 전환으로 제공)

* **좌측 패널 (40%): 게시물 원문 및 정보**
  * 게시글 제목, 작성자(닉네임), 카테고리 배지, 수명 상태 배지(`LIVE` / `READ`), 남은 시간 카운트다운 타이머.
  * 작성자가 등록한 본문 텍스트 및 이미지/링크 (채팅과 별개로 독립 스크롤 제공).
  * 화면 확보를 위해 좌측 패널을 완전히 숨기거나 펼칠 수 있는 **패널 접기 토글 버튼(`<`)**을 제공.

* **우측 패널 (60%): 실시간 채팅**
  * **상단 배지**: 현재 이 게시물에 접속해 있는 실시간 동접자 수 표시 (`[👀 247명 접속 중]`).
  * **채팅 영역**: 웹소켓 기반 실시간 채팅창. 본인 메시지는 우측, 타인 메시지는 좌측에 버블 형태로 표시.
  * **이모지 반응**: 특정 채팅 메시지에 이모지 반응(👍 ❤️ 😂 😡 등) 기능 제공.
  * **답장(Reply)**: 특정 메시지를 인용하여 대답할 수 있는 기능 지원.
  * **하단 입력창**:
    * `🟢 LIVE` 상태일 때만 입력창 활성화.
    * `🟡 READ` 상태로 전환 시 *"읽기 전용 게시물입니다. 새 글을 작성해보세요!"* 안내 문구와 함께 입력 잠금. 새 게시물 작성 페이지로 유도하는 링크 버튼 제공.

* **모바일 레이아웃 (반응형)**
  * 화면이 좁은 모바일 기기에서는 좌/우 분할 대신 `[게시물 원문] [실시간 채팅 🔴]` 형태의 **상단 탭 전환 방식**으로 레이아웃이 자동 조정됨.

## 4. 주요 기능 상세 정의

### 4.1 3단계 콘텐츠 수명 주기 (Data Lifecycle)

모든 게시글(게시물)은 생성 시점부터 서버 오케스트레이션 타이머에 의해 엄격하게 제어됩니다.

| 단계 | 상태 | 소요 시간 | 기능 및 유저 권한 | 운영 및 서버 관점 |
| :--- | :---: | :---: | :--- | :--- |
| **1단계** | **🟢 LIVE** | 생성 후 0~24시간 | 실시간 채팅 참여 가능, 상단 HOT 카드 진입 권한 보유, 답장·이모지 반응 가능 | 트래픽 밀집 구간. 웹소켓(WebSocket) 통신 및 Redis 인메모리 서빙으로 초고속 처리. |
| **2단계** | **🟡 READ** | 생성 후 24~48시간 | 채팅 입력창 비활성화. 이전 대화 기록 스크롤 및 읽기만 가능 | 데이터 복기 구간. 디스크 DB 쿼리로 전환하여 웹소켓 서버 부하 해소. |
| **3단계** | **🔴 DELETE** | 생성 후 48시간 이후 | **플랫폼에서 영구 삭제** (유저 조회 불가) | 데이터 자동 파기(Purge). DB 용량 최적화 및 묵은 도배·악성 콘텐츠 리스크 100% 소멸. |

### 4.2 익명 닉네임 시스템

* **작동 원리**: 로그인·인증 없이 접속하는 즉시 UUID 기반의 임시 유저 세션이 생성되며, 인터넷 유머 정서를 반영한 조합형 닉네임이 무작위 부여됨.
* **닉네임 조합 알고리즘**: `[상태 및 감정 수식어]` + `[동물·직업·캐릭터 명칭]`
  * *예시 1*: "졸린 눈의" + "해달" = **졸린 눈의 해달**
  * *예시 2*: "커피 네 잔째인" + "직장인" = **커피 네 잔째인 직장인**
  * *예시 3*: "분노의" + "키보드 워리어" = **분노의 키보드 워리어**
* **커스텀 권한**: 유저는 프로필 변경 팝업에서 원하는 닉네임으로 언제든지 수정 가능. 수정된 닉네임은 로컬 스토리지에 보존되며, 로그인 계정 연동 시 서버에 영구 저장.
* **기기 연속성**: 닉네임 및 참여 이력 유지를 원하는 유저는 소셜 로그인(구글·카카오·네이버)으로 계정 전환 가능.

### 4.3 실시간 HOT 산출 알고리즘 (가중치 방식)

상단 HOT 카드 영역에 노출될 게시물은 단순 누적 조회수가 아닌, '현재 순간의 핫함'을 측정하는 가중치 스코어링 시스템으로 결정됩니다.

* **Score 계산식**: `(현재 게시물 동접자 수 × 0.5) + (최근 5분간 채팅 수 × 0.3) + (최근 5분간 이모지 반응 수 × 0.2)`
* **갱신 주기**: 10초 단위로 스코어를 재계산하여 HOT 카드 순위를 동적으로 업데이트.
* **어뷰징 방어**: 동일 IP/세션의 중복 카운팅 차단. 급격한 스코어 이상 증가 시 자동 플래그 처리 후 관리자 검토 큐로 전송.

### 4.4 게시물 작성 및 분류

* **생성 방법**: 메인 화면의 `[+ 새 글 쓰기]` 버튼으로 제목·내용·카테고리를 선택하여 즉시 생성. 익명·로그인 유저 모두 생성 가능.
* **카테고리 분류**: 사회·정치 / 경제·주식 / 스포츠 / 연예·문화 / 가상자산 / IT·게임 / 자유
* **글 작성 제한**: 도배 방지를 위해 동일 세션(또는 계정)당 1시간에 최대 3개의 게시물 생성 가능.

## 5. 운영 정책 및 신고 시스템

### 5.1 콘텐츠 운영 원칙

* **자동 필터링**: 금칙어 DB 기반의 욕설·혐오 표현 1차 자동 필터링. AI 기반 맥락 감지로 우회 표현 2차 필터링.
* **신고 기능**: 모든 채팅 메시지 및 게시글에 신고 버튼 제공. 신고 사유: 욕설/혐오, 허위정보 유포, 스팸/도배, 개인정보 노출 등.
* **누적 신고 처리**: 단시간 내 다수 신고가 접수된 메시지는 자동 블라인드 처리 후 관리자 검토.

### 5.2 제재 기준

| 위반 유형 | 1차 | 2차 | 3차 |
| :--- | :--- | :--- | :--- |
| 욕설·혐오 표현 | 메시지 삭제 + 경고 | 24시간 채팅 정지 | 영구 IP 차단 |
| 스팸·도배 | 메시지 삭제 + 자동 Rate Limit | 24시간 이용 정지 | 영구 차단 |
| 허위정보·명예훼손 | 게시글 삭제 + 경고 | 7일 이용 정지 | 법적 조치 검토 |

### 5.3 법적 면책 및 컴플라이언스

* 플랫폼은 **정보 교환의 場(장)을 제공하는 중립적 중개자**이며, 개별 게시물의 내용에 대한 법적 책임을 지지 않음을 이용약관에 명시.
* 개인정보보호법 및 GDPR 준수: UUID 기반 익명 세션의 IP 로그는 최대 30일 보관 후 파기. 수사기관 적법 요청 시에만 제공.

## 6. 알림(Notification) 및 바이럴 전략

### 6.1 알림 시스템 (FOMO 극대화)

* **HOT 진입 알림**: 유저가 생성하거나 참여한 게시물이 HOT 상위 3위에 진입 시 푸시 알림 발송.
* **만료 임박 알림**: 관심 표시한 게시물의 수명이 1시간 남았을 때 알림.
* **대화 알림**: 내 채팅에 답장(Reply) 또는 이모지 반응이 달렸을 때 실시간 알림.

### 6.2 공유 및 바이럴 전략

* **URL 공유 시 OG 태그 최적화**: 공유 링크 미리보기에 *"이 게시물은 7시간 23분 후 사라집니다"* 와 같은 긴박감 메시지 자동 삽입 → SNS 공유 시 FOMO 클릭 유도.
* **게시물 임베드**: 외부 사이트나 SNS에 게시물의 실시간 채팅 위젯을 임베드 코드로 삽입 가능.
* **인기 채팅 캡처 카드**: 라이브가 종료(READ 전환)되기 직전, 가장 많은 반응을 받은 채팅 발췌문을 이미지 카드로 자동 생성하여 저장·공유 가능.

## 7. 비즈니스 모델 (BM) 및 수익화 전략

### 7.1 타임어택형 디스플레이 광고 (DA)

* **개요**: 48시간 후 무조건 파기된다는 긴급성을 광고 구좌에도 적용.
* **구조**: 특정 이슈·이벤트에 맞춰 관련 카테고리 게시물 전체에 24시간 동안 노출되는 타임어택형 배너·팝업 광고 구좌를 광고주에게 판매.
* **예시**: 스포츠 브랜드사가 월드컵 결승전 당일 스포츠 카테고리 전체 게시물에 24시간 배너 집행.

### 7.2 프리미엄 게시물 (유료 입장 모델)

* **개요**: 전문가·인플루언서·저명인사가 개설하는 '유료 게시물' 도입.
* **구조**: 일반 유저가 해당 게시물의 채팅에 참여하려면 인앱 재화(팝콘·별 등)를 지불해야 함. 플랫폼은 결제 금액의 20~30%를 중개 수수료로 수취하고, 나머지는 게시물 개설자에게 귀속.

### 7.3 광고 없는 프리미엄 구독 (SaaS 모델)

* **개요**: 광고 제거, 닉네임 고급 커스터마이징, 채팅 기록 개인 아카이브(48시간 후에도 본인만 조회 가능) 등 혜택을 월정액 구독 서비스로 제공.

## 8. 기술 스택 및 시스템 아키텍처 제안

* **Frontend**: Next.js (Web — SEO 최적화 및 OG 태그 서버사이드 렌더링에 유리) / Flutter (크로스 플랫폼 앱 확장 고려 시)
* **Real-time Engine**: Node.js + Socket.io 또는 Go (Golang) 기반 Gorilla WebSocket (대규모 동시 채팅 트래픽 처리를 위해 Go 스택 강력 권장)
* **In-Memory Layer**: Redis (LIVE 상태 채팅 데이터 초고속 입출력 큐 관리 및 HOT 실시간 스코어 Sorted Set 관리)
* **Database**: PostgreSQL (READ 상태 아카이빙 데이터 보존 및 48시간 경과 데이터 배치 삭제 처리)
* **Push Notification**: Firebase Cloud Messaging (FCM)
* **Infrastructure**: AWS (ECS/Fargate + Auto-scaling), CloudFront CDN 연동
