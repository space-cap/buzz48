# 실시간 검색 및 무한 스크롤 기능 추가 계획서

본 문서는 Buzz48 피드(게시판) 영역에 실시간 검색(Search) 기능을 적용하고, 기존 수동 더보기 버튼 대신 자동 무한 스크롤(Infinite Scroll) UX를 도입하기 위해 실행된 설계 및 구현 명세서입니다.

---

## 1. 배경 및 기획 의도

1. **48시간 휘발성 도메인의 특성**:
   - Buzz48은 48시간이 지나면 글이 소멸하는 타임라인 커뮤니티입니다.
   - 데이터가 영구 보존되지 않고 끊임없이 순환하므로, 정적인 페이지네이션(1, 2, 3...) 방식은 오히려 데이터 스킵이나 중복 노출을 유발합니다.
   - 따라서 물 흐르듯 실시간으로 피드를 확인하는 **무한 스크롤**이 최적의 탐색 UX로 선정되었습니다.

2. **실시간 주제 탐색 강화**:
   - 빠르게 소멸하는 방들 속에서 유저들이 관심사(예: 번개팅, 특정 스포츠 경기, 금융 소식)를 즉각 찾아서 댓글에 난입할 수 있도록 **실시간 키워드 검색**을 제공합니다.

## 2. 구현 상세

### 2.1 백엔드 API (Go / Fiber / pgx)
- **핸들러**: [post.go](file:///h:/lee/buzz48/backend/internal/handler/post.go)
- **API 시그니처**: `GET /v1/posts?category={category}&search={search_keyword}&cursor={cursor_timestamp}&limit=15`
- **쿼리 로직**:
  - `search` 파라미터 유무에 따라 SQL 분기 쿼리를 구성했습니다.
  - 대소문자 구분을 하지 않는 부분 매칭을 위해 PostgreSQL `ILIKE` 연산자를 활용했습니다:
    ```sql
    AND (title ILIKE $4 OR content ILIKE $4)
    ```
  - `cutoff` 기준(현재 시간 - 48시간)과 결합하여 항상 최신 생존 글 중에서만 검색 필터가 동작하도록 강제합니다.

### 2.2 프론트엔드 UI & UX (Next.js / React / TypeScript)
- **API 클라이언트**: [api.ts](file:///h:/lee/buzz48/frontend/src/lib/api.ts) ➡️ `getPostsAPI` 에 `search` 파라미터 결합 처리.
- **메인 피드 뷰**: [page.tsx](file:///h:/lee/buzz48/frontend/src/app/page.tsx)
- **실시간 검색 바**:
  - 카테고리 탭 리스트와 글쓰기 버튼 사이에 플렉스 레이아웃으로 균형 있게 배치했습니다.
  - 검색어 지움 버튼(`×`)을 제공하여 한 번의 클릭으로 전체 목록 복원이 가능하도록 보완했습니다.
  - 카테고리를 이동할 때는 검색 상태를 강제로 리셋하여 해당 카테고리의 청정 데이터가 우선 정렬되도록 흐름을 정돈했습니다.
- **자동 무한 스크롤**:
  - 목록 최하단에 보이지 않는 센서 트리거 `<div ref={loadMoreTriggerRef} />`를 장착했습니다.
  - 브라우저 표준 `IntersectionObserver` API를 활용하여, 스크롤바가 바닥에 도달하는 시점을 감시하고 감지 시 `handleLoadMore`를 백그라운드에서 자동 연동합니다.
  - 추가 로드 중일 때의 쾌적한 피드백을 위해 `🔄 다음 글을 가져오는 중...` 인디케이터가 자동으로 등장하고 사라집니다.

## 3. 성능 및 데이터베이스 최적화

- **인덱싱 최소주의**:
  - 48시간 초과 데이터는 배치 워커에 의해 청소되므로 데이터베이스 크기가 작게 제어됩니다.
  - 따라서 일반적인 상황에서는 DB Full Scan 부담이 거의 없으나, 추후 활성 트래픽 확장을 고려하여 제목과 본문에 PostgreSQL의 `pg_trgm` 확장 기반 `GIN` 인덱스를 걸도록 설계에 반영해 두었습니다.
